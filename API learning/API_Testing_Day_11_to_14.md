# API Testing — Day 11 to Day 14

---

# Day 11: API Testing Fundamentals (Theory)

## Topics:

- What is an API, client-server model
- REST principles
- HTTP methods: GET, POST, PUT, PATCH, DELETE
- HTTP status codes: 2xx, 3xx, 4xx, 5xx
- Request structure: URL, Headers, Params, Body
- Response structure: Status, Headers, Body
- Reading JSON

## Assignment:

1. Given a sample JSON API response, identify and label all key-value pairs, nested objects, and arrays.
2. Match 8 given HTTP status codes to their correct meaning.

---

# Day 12: Postman Basics

## Topics:

- Postman interface: Collections, Environments, History
- Sending a GET request
- Creating and organizing a Collection
- Query params vs Path params
- Sending a POST request with JSON body
- Reading the response panel (status, time, size, body)

## Assignment:

1. Using a public test API, send GET, POST, PUT, and DELETE requests. Screenshot and note the status code and response for each.

---

# Day 13: Manual API Testing — Validating Responses

## Topics:

- Validating status codes (positive/negative scenarios)
- Validating response body values manually
- Headers: Content-Type, Authorization
- Basic Auth vs Bearer Token vs API Key (concept)
- Negative testing: missing fields, wrong data types, invalid auth
- Common API bugs to watch for

## Assignment:

1. Write 8–10 manual API test cases (positive + negative) against the same public API, in Action/Data/Expected Result format.
2. Execute them in Postman and record actual results against expected.

---

# Day 14: Postman — Collections, Variables & Practical Workflow

## Topics:

- Environments and variables (base URL, tokens)
- Chaining requests (using one response in the next request)
- Organizing a full Collection per feature/module
- Exporting/sharing a Collection
- Where manual API testing fits in the QA workflow

## Assignment:

1. Build one complete Postman Collection covering Create → Read → Update → Delete for a sample resource, using environment variables (no hardcoded URLs/IDs).
